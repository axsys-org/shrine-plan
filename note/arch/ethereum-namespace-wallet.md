# Ethereum compiler and namespace wallet

The wallet application owns transaction decisions in Shrine. The contract
compiler produces all EVM artifact content in PLAN. This supersedes the Python
wallet and assembler boundaries in [the Sepolia v0 record](foil-sepolia-v0.md).
The deployed contract and its historical evidence remain unchanged.

## Compilation

`contracts/checked.foil` builds an expression with the Foil contract DSL.
`contract-source` compiles that module, `contract-lower` constructs restricted
executable PLAN, and `restricted-plan` validates its closed graph. `contract-evm`
produces symbolic EVM instructions. `contract-assemble` resolves labels, emits
instructions, builds the ABI dispatch and constructor, and serializes the
artifact. Its Keccak dependency is compiled Foil code in `ethereum_keccak`.
Python supplies no compiler semantics on this path. Keccak follows the
[Keccak specification](https://keccak.team/keccak_specs_summary.html); transaction
encoding follows [EIP-1559](https://eips.ethereum.org/EIPS/eip-1559).

The assembler preserves the existing restricted semantics, fault ordering,
nonpayable entry checks, fixed argument arity, and 24,576-byte runtime limit.
The existing Sepolia artifact provides a byte-for-byte compatibility fixture.
The test suite also compares generated bytecode execution in PyEVM with PLAN
results, independently checks Keccak padding, and retains the old Python
assembler as a test oracle.

## State and effects

`ethereum_wallet_app/install` creates a behavior and root application record in
an ordinary namespace. The root holds the typed wallet state; intent and stream
children expose the corresponding records. A typed request wraps the command
sum so namespace input contains a nominal pail. The behavior admits commands and
updates its records atomically. It accepts no arbitrary state patch. Embeddings
use `ethereum_wallet_app/access`: its guarded handler forces each candidate
inside `Try` and returns a rejected ACK with the prior state when behavior
evaluation fails. The standalone supervisor uses this handler.

`ethereum_wallet/apply` owns intent identity, nonce reservation, fee and gas
bounds, transaction construction, signature scalar validation, transaction hashes,
receipt state, stream cursors, event batches, and acknowledgments. Intent ids
bind immutable destination and data. Duplicate requests preserve state;
conflicting reuse fails. Nonces advance monotonically after a valid quote.

The native foot reads RPC observations through `Fetch`, asks the private signer
for a signature over the saved transaction digest, and submits resulting
commands to the supervisor. It reads state again after each acknowledged change.
`helm/supervisor/run_keeping` saves changed state before replying. Broadcasting
therefore requires signed bytes already present in the saved namespace. A lost
broadcast response retries by transaction hash and the same raw bytes.

The standalone saved-world entry stores only the namespace and its resume code.
On restart it obtains fresh RPC and signing capabilities over its input pipe.
The console exposes prepare, subscribe, acknowledge, status, and cycle. Normal
Shrine callers can use the typed commands directly; the same polling foot can
attach through transferred mailbox capabilities.

## Events and receipts

The foot checks the chain id, canonical headers, and log block hashes. It
revalidates the retained anchor and scan endpoint before committing a scan.
The reducer checks the expected cursor, ancestor, parent links, contiguous block
numbers, and scan limit. It retains canonical headers to find a common ancestor.
Reorganizations append removed events in a new batch. Acknowledgments remove
only batches at or below the acknowledged sequence; unknown sequences fail.
The current filter selects the example contract's Result event.

These checks detect inconsistent observations from an RPC provider; they do not
implement an Ethereum light client. A chain may reorganize after the final RPC
read. Subsequent cycles repair the saved view. A canonical receipt, including a
reverted receipt, is an observation of inclusion rather than a finality claim.
Event confirmation delay is a block-count policy.

## Host boundary and limits

`host.py` creates and opens private keystore files, holds the unlocked key,
reports its address, and signs 32-byte digests through an authenticated loopback
endpoint. It neither constructs transactions nor contacts Ethereum. The signer
capability can authorize arbitrary digests; its bearer token grants that power.
It remains outside deterministic namespace state. Private key bytes never enter
PLAN. The colocated password enables unattended local tests, not a second
security factor.

The native runtime supplies HTTP, mailboxes, scheduling, console I/O, and saved
images. Python currently supplies signing-capability transport and process/file
launching. None of those host operations intrinsically requires Python.
`eth-account` and `eth-keys` are signer dependencies. Web3 and PyEVM are test-only
oracles. RLP and Keccak do not cross the host boundary.

Limits remain explicit: Sepolia chain id, zero ETH value, empty access list,
2-gwei tip ceiling, 30-gwei total fee ceiling, 1-million gas ceiling, and
0.002-ETH maximum gas budget per intent. There are at most 1,024 intents and
1,024 unacknowledged event batches per stream. Event scans start after genesis
and process at most 128 blocks. Header retention is currently unbounded.
The wallet trusts its signing capability and does not recover the signer inside
PLAN. It has no fee replacement or automatic nonce-gap repair. Local supervisor
ownership serializes writes; independent worlds must not share one account's
nonce authority. Privacy and rollup settlement remain undecided.

## Acceptance evidence

The migration passes 17 Python-driven tests and 24 native Foil assertions, plus
`contract-tests` and `restricted-plan-tests`. The EVM gate checks 474 arithmetic
cases against PLAN, the deployed artifact's exact bytes, and rejection of
invalid assembly. Independent cryptographic checks cover 11 Keccak input
lengths and 12 signed EIP-1559 transactions across nonce and payload boundaries.

The wallet integration test runs a real saved Shrine namespace and native
`Fetch` against a test-only RPC bridge to PyEVM. It checks signature recovery,
restart after signing, duplicate and conflicting intents, rejection without
killing the supervisor, accepted broadcast with a lost success response,
canonical receipts, event replay, reorganization removals, and cumulative ACKs.
The signer test checks authentication, Origin rejection, operation scope, and
native Foil transport. Key-file tests check permissions and reopening.

A read-only native RPC probe also checks Sepolia chain id 11155111, the deployed
runtime hash, and the recorded Result event in block 12079948 against the
historical deployment evidence. It uses `ethereum_chain_probe.foil`, native
`Fetch`, and Foil Keccak. This migration sends no additional Sepolia transaction.
The standard-library-only build launcher produces the same deployed bytes.
