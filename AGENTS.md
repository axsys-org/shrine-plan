# Canvas operating covenant

Canvas is the place where native software is constructed, used, inspected, and
recombined. Every successful construction must become material for further
construction. This constrains every implementation change, not one demonstration.

- Use Shrine records, references, cases, care, forms, crews, overlays, guarded
  operations and history. Use Grove/Rex/Foil for definitions and computation.
  Do not create a universal Thing wrapper, application registry, host domain
  evaluator, or a second dependency engine.
- A spreadsheet, compiler, image editor, game and workspace are ordinary native
  constructions. No application-type dispatch belongs in the browser or host.
- A polished visual region is not sufficient. Every meaningful part must resolve
  to its exact native subject, slot/typed element, implementation and basis.
  Repetition is parameterized and bounded, not a million persistent UI records.
- Reuse successful constructions without export or host registration. Definitions,
  source, diagnostics, presentations and constructors are themselves native material.
- Use existing native contracts before adding machinery. Resolve mismatches as
  explicit native work; never hide a semantic adapter in JavaScript or Python.
- Models may author, investigate and propose. Established software must work with
  the model disconnected. Browser/host responsibilities are rendering, input,
  authentication, physical boundaries, transport and resource supervision.
- Common representation does not erase native types, authority, ownership or the
  distinction between referencing code and permission to execute it.
- Preserve partial work, original identities, unrelated slots, drafts and existing
  working behavior. Removing a presentation does not delete its subject.
- Preserve compatible historical worlds and dirty work. Never reinterpret a
  journal with a changed engine. Archive superseded source once outside iCloud.
- Native checks, real browser interactions, resource measurements and observed
  usability are separate evidence. Never call the product complete because a
  fixture, mock, animation or task record says it passed.

The connected acceptance is editor → spreadsheet → compiler/IDE → image operations
→ dictionary/game/simulation → editing the actual workspace. Freeze host application
code after the general rendering/input boundary; any further host capability needs
an explicit generic-boundary rationale and use by independent constructions.

Run serial disposable native workers. Retain at most two unresolved failure stores;
discard diagnosed copies while preserving source, input, logs and receipts. Never
truncate live pins. Do not relax memory guards to conceal an endurance failure.

## Standing conceptual alignment

- Inputs are native typed NS trees and values: records, references, sequences,
  maps, matrices, graphs and derived values. An application's copied host model
  is not the input. The machinery operating on these values is native material
  too, with the same ability to be inspected and composed again.
- Manual construction, model authoring, decoded files, applying machinery to
  existing subjects, and importing native constructions converge on this same
  world. They are entry paths, not separate product modes.
- Model work interprets, finds, binds, repairs, invents, extends, presents and
  crystallizes. Prefer extending existing machinery. Successful adapters and
  derived computations remain native material available for subsequent reuse.
- Presentation may take any useful form while preserving exact correspondence.
  Resolve repeated elements generatively on the requested basis, rather than
  maintaining enormous parallel binding structures.
- Use browser Canvas/SVG/raster rendering freely for dense or custom geometry,
  graphs, images, games, timelines, handles and transient previews. This is a
  presentation escape hatch, not a new ontology or a fixed widget catalogue.
  Prefer DOM/native controls where text entry, focus, IME and accessibility
  benefit. Do not expand dense surfaces into thousands of DOM boxes by default.
- Meaningful drawn regions and hit tests must resolve through pinned native
  correspondence to exact subjects, slots, typed selections or derived results
  on the displayed basis. Coordinate conversion and drawing belong at the host
  boundary; gesture/key meaning, state transitions and application algorithms
  belong in native definitions bound to the current focus and context.
- Preserve room for UI Foundry, broader care/template reuse, networking and
  alternate execution backends. These are future directions, not requirements
  to introduce abstractions before concrete constructions need them.
- The intended experience is working with native things while appropriate
  software grows around them. Established operations work without the model.

Apply this guidance while continuing the current implementation checkpoint;
do not restart or replan it unless a concrete architectural conflict appears.

## Current working mode: sustained native use

Read, build, import, compose, correct and reuse in the live world. Search existing
native definitions and partial machinery before inventing a missing piece. Shared
subjects and exact references survive every presentation; matching labels never
establish identity. Manual, file and model construction converge on those subjects.
Reuse individual field mappings, projections, renderers, actions and correspondence
functions, not only complete templates. Retain successful adaptations and their
evidence so the next construction can use them without another model call.

Do not return to runtime work or broad regression campaigns after a successful
interaction. Investigate an actual failure exposed by use, repair the narrowest
responsible native definition or binding, verify it, and resume use. Preserve a
focused permanent regression for discovered shared/kernel invariant failures.
The unpassed 150 ms target is recorded, not the current activity. Automatic repair
must preserve retained commitments, factual uncertainty and authority; a repair
does not authorize weakening a constraint. Report actual use and remaining gaps.

## Material, binding and media alignment

Select/create/import native material, apply or construct machinery, and reuse the
result as material. Constructions may expose, derive and mutate together; do not
introduce separate projection/mutation/application categories. Keep cared inputs,
authorized write targets and derived result paths distinguishable. Care selects
dependency scope; it does not manufacture type compatibility or grant authority.
Repeated and recursive presenters resolve exact native paths on the displayed
basis. Reuse individual UI/behavior fragments, not only whole surfaces.

For ingestion, retain original bytes with their hash/version and provenance,
then a faithful addressable native representation. Decoding and optional semantic
interpretation are separate. Partial projections may reuse existing identities;
names or model guesses alone do not establish identity. Uninterpreted material
remains usable. Anchors bind exact versioned ranges, cells, regions or masks to
native subjects or slots. Only explicitly supported actions write back, producing
a derived version while preserving the original evidence.

Native masks/regions are primary spatial observations. Host decoding/perception
may segment, track or register new media; Shrine owns anchors, identities,
history, region algebra and derived meaning. Comparisons need compatible or
explicitly registered coordinate bases and known identity correspondence.
Tracking uncertainty, occlusion, missing observations and registration failure
must stay explicit; a mask difference does not by itself prove semantic change.
Keep corrections and downstream evidence. Reuse conventional tracking between
model interventions; do not ask a model to reinterpret every frame. Crystallized
rules retain their checked scope and evidence rather than becoming universal
facts from a few examples. Prove one small real ingestion/use loop before adding
formats or a host framework.

## User navigation refinement

The everyday view leads with named flow anchors, people, projects, files and useful
native constructions. Technical paths, installation records and compiler metadata
belong behind an explicit inspection disclosure. These are presentations of the
same native identities, never a copied user-facing data model. Restore persistent
flow placements and keep agent results beside their originating work; do not send
users to new blank canvases. A hideable activity panel shows factual native reads,
proposals, results and unresolved attention, with exact details on inspection.
Unspecified field sources require native search and proposed bindings. Unknown
personal facts remain unknown. Never invent a person, age, wealth or avatar merely
to fill a requested presentation. Ask locally if identity/meaning is ambiguous.
