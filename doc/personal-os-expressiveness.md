# Personal OS: connected expressiveness map

User direction, 2026-10-03 UTC. This extends the canonical harness and sequential
construction contract. It is a proving map, not a registry of privileged app types
or a claim that these constructions exist yet.

All inputs, computations, actions, results and presentations remain native
NS/Grove/Foil/Goo material. Each successful construction must supply reusable
material for the next. The host may supply general rendering, input and physical
capabilities; it must not gain a subsystem for each application below.

Build sequentially in the live world: establish missing structure, show the
native change, surface the structure, add the small local behavior needed for
use, then extend or reuse it. Retain shared identities and original evidence.

## Construction families

1. **Core information and editing:** text editor; rich document editor;
   Markdown editor/viewer; PDF/document reader with anchored selections;
   file/artifact browser; search across NS, files, results and references;
   dictionary/glossary/knowledge browser; notes/personal wiki.
2. **Structured data:** table; spreadsheet; form/record editor; CSV/XLSX inspector;
   JSON/XML tree editor; pivot/grouping/aggregation surface; filter/query builder;
   charting/analytics dashboard.
3. **People and organization:** contacts; people directory; org chart;
   relationship graph; CRM-like relationship tracker; team/workload view;
   communication/history view around a Person or Organization.
4. **Time and planning:** calendar; timeline; Gantt/project planner; task manager;
   Kanban; reminders; daily planner; resource/workload planner; personal goals,
   habits and recurring routines.
5. **Software development:** source editor; project/file tree; AST browser;
   compiler surface; diagnostics; REPL; debugger/inspection surface; test runner;
   diff/review; an IDE composed from those pieces.
6. **Visual and media:** image viewer/editor; mask/region editor; image comparison;
   annotation; media browser; GIF/video viewer; video timeline/clip editor;
   object tracking/anchored regions; audio waveform/transcript surface.
7. **Spatial and geospatial:** map; GIS-like layers; geometry/region editor;
   satellite comparison; property/building/site viewer; route/movement/trajectory
   view; region-over-time change analysis.
8. **Graphs and systems:** generic graph editor/viewer; dependency graph;
   knowledge graph; workflow/process graph; state machines; causal/provenance
   graph; NS dependency/cascade inspector.
9. **Simulation and interactive worlds:** cellular automaton; general simulation;
   game board; small real-time game; agent/world simulation; physical or
   rule-based spatial systems; instrument/control-panel UI.
10. **Research and investigation:** document research workspace; evidence board;
    case/investigation timeline; entity/relation explorer; source/provenance
    inspector; comparative analysis; literature organizer; combined datasets,
    documents and notes.
11. **Personal operations:** job search; application/interview planning;
    finance/budget; expenses; subscriptions/bills; travel; household inventory;
    personal projects; reading/media queue.
12. **Business and operations:** CRM; project management; inventory; operational
    dashboard; claims/cases; risk analysis; scheduling/resource management;
    internal workflow surfaces; reporting/analytics.
13. **Agent-native work:** agent task queue; decisions/ambiguities; proposed
    native diffs; broken commitments/repairs; agent results; action provenance;
    approval/authority; background observations; reusable machinery/search.
14. **Meta and self-hosting:** NS structure editor; Grove editor; construction
    inspector; binding inspector; presenter editor; local semantic behavior
    editor; provenance/history; workspace editor; Shrine configuration;
    eventually Shrine using Shrine to modify Shrine.

## Connected proof

- Table + typed editing + formulas → spreadsheet.
- Spreadsheet + Task references + temporal projection → planner.
- Planner + calendar presentation + workload computation → project environment.
- Source editor + AST + compiler + diagnostics → IDE.
- Image + masks + temporal observations + geometry → change analysis/GIS.
- Documents + People + Events + graph + timeline → investigation workspace.

For each connection, retain exact native input/output references, the reused
definitions and their implementation pins, the smallest genuinely missing
artifact, its checked scope, and observed use. Reuse pieces at any scale, not
only entire surfaces. The meaningful count is how much machinery is reused and
what new capability it enables, not how many app-shaped screens exist.

No example employment, financial, medical or business facts become facts about
the user merely because this list mentions an application category. Use real
authorized inputs or clearly identified synthetic fixtures when requested.

## Real public-file construction — 2026-10-03

The current live world is `grove-personal-v25` on loopback port 8186. The
preceding stopped-service account describes the historical v21/v22 checkpoint;
it is not the current service state. Historical worlds and the v25 engine were
preserved. Resource/endurance acceptance is still outstanding.

The Tōhoku flow uses an original 65-event USGS CSV query, a separate one-event
GeoJSON query, the official USGS shaking-map JPEG, and the FDSN event-service

and the first-page PNG are explicit host-decoded derivatives with a receipt;

earthquake, spreadsheet, JSON-query, or geospatial evaluator was introduced.

Browser use established counts of 65, 5, and 1 at minimum magnitudes 6, 7, and
8. Selection and reverse chronological ordering retained the original mainshock
focus: event `official20110311054624120_30`, original CSV row 5, column 4, value
9.1, source case 10. The uploaded JPEG rendered byte-identically to the download.
The PDF cover and extracted text were opened in the real browser.

Live use required small generic host repairs: align native request/upload bounds,
permit bounded passive inline PNG/JPEG/WebP images, let inspection take priority
over viewport selection, preserve disclosure state through patches, and keep
the empty-flow prompt hidden when real occurrences exist. Authentication and

the source bytes are retained. Overlay-backed proposal previews can be rejected
by the current stale guard; these additions used checked structure proposals,
then actual installed-frame/browser verification.
