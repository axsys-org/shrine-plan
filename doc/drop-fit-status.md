components, and drop exact native material together on one working board. Labels,
arrows, surrounding components and bound data supply interpretation context.
The full `sketch-novel-drag-known-demo.html` source has been inspected. Its six
sequences are experience references; its data, native receipts and timings are
scripted and are not evidence for the implementation.

Custom-component authoring adds blue picture marks and orange contract marks.
Explicit boundaries, cardinalities, ports, axes, anchors, rails and snaps build a
local contract card. Unknown write targets stay holes. Derived expressions are
intent until resolved to checked operations or accepted pure-function proposals.
The newly supplied §10 type definitions are not present locally; do not claim
wire compatibility with an unseen schema.

The latest execution clarification permits JS for simple local mechanics.
Grove/Shrine retains reusable component definitions, semantic behavior, durable
state, checked bindings and history. No model-authored host application evaluator.

Implemented foundation: native arrangement storage and per-block revisions;
content identities and placed/unplaced conservation; bounded structural matching;
protected label facts; retained proposals; event receipts and guarded undo.
Fit candidates currently validate content identity only. They cannot be activated
as working applications. This limitation is explicit in their response.

Verification: `fit_core` compiles (28 declarations); all 20 native core checks
passed, including content conservation, cycles, structural shapes, and label
ambiguity. The transaction module compiles; all 11 native persistence tests pass, including
first write, idempotent replay, stale edits, exact undo and monotonic history.
Derived/group-label checks also pass. Browser/HTTP integration
has not been tested in a launched new world.
