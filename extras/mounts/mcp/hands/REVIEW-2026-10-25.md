# Review of Codex's native views work, 2026-10-25

Read-only review of the uncommitted working tree on `ic-bare-loop` (20 modified files, 33 new, +992/-73 in the
diffs plus ~2,900 new lines). Nothing was run; nothing was changed. Line numbers are into the current files.

## Verdict in one line

The architecture is right and better than the plan asked for; the kernel changes are not safe to put under the
saved world yet, the graph views diverge from the Python they replace in ways a reader would notice, and the
explorer still reads from Python. Three stop-ship items, then a list of fixes.

## What Codex built

- **A demand protocol for views** (`src/foil/view_protocol.foil`). A view does not get a reader. It returns a
  plan: `done tree`, `need read next` (give me this input, then continue), `graft source` (that address is the
  answer, nothing copied), or `fail`. The kernel interprets the plan (`lain_peek.foil:625-661`), serves each
  `need`, memoises repeated reads, counts steps against a fuel of 256, records every observation. Views stay pure
  and still reach across the store. This is the right shape and it is what makes composition (a view over a view)
  possible.
- **A reverse-reference index** (`src/foil/reference_index.foil`): `into: target → edges{holder, slot, target}`,
  updated inside every commit (`shrine.foil:665-685`), with a pinned snapshot per epoch that changed it, read at
  `/r/<len>/<target>` (`lain_peek.foil:353-369`). Literal-only edits leave it untouched. MCP `referencing` now
  reads it instead of walking the world.
- **Addressable computed children**: `/x/<cell>/<child>` resolves through the longest prefix holding a weft
  (`cell_address`, `lain_peek.foil:1263-1279`). Virtual folders are readable at y and z.
- **Epoch pins**: `/h/<care>/e<epoch>/...` freezes a reader at that epoch, including that epoch's system
  publication (`namespace.foil:87-97`), so a historical read of a derived view uses the definitions of its time.
- **Caches in the supervisor's memory only**: a view cache of 256 entries validated by re-resolving observations
  (`view_cache.foil`), a render cache of 64 entries / 8 MiB (`view_render.foil`). Nothing derived is written as
  records. Correct per the scheme.
- **Operators** (`view_ops.foil`, `view_walk.foil`): children, outline, follow, referencing, collection, gather,
  count, compose; a bounded walker over forward and incoming edges with a trail for cycles.
- **Graph views in Foil** (`extras/mounts/mcp/graph_*.foil`): relations, placements, identity closure over `same`,
  "as a world", union with conflicts, beneath; 8 named definitions installed at `/<self>/weft/graph/*`; HTTP routes
  `/graph/{links,by,around,unfold,union}` that mimic the Python index's JSON.
- **Tests**: 167 checks over 15 suites pass in Codex's last full run (`.check/native-views/test-native-37`), 174 in
  another, 19 supervisor checks in the run that finished at 21:02. No failures in any run.
- **An offline migration proof**: a C adapter plus a Reaver script re-indexed a clone of the saved world (5,541
  records, 0 changed, 0 removed, 874 old cells retained, restart verified). Not wired into the runtime.

Codex's own STATUS.json is honest: "implementation unfinished, not deployed", "performance_regression_proven_absent:
false", "UI has not switched to native routes", "~110 ms warm for a 100-node page".

## Stop-ship, in order

1. **The saved-world format changed and nothing in the runtime migrates it.** `sov` gained a fifth field
   (`shrine.foil:407`). `sov/reindex_references` exists (`shrine.foil:687-716`) but its only caller is a test. A
   saved world resumes on its captured old kernel, so it keeps working only as long as the new code is never handed
   the old namespace; the `mounted-with` entry added in `src/reaver/eden.rvr:39-43` exists for exactly that hand-off
   and nothing calls it. Worse: the new `mcp_mount.foil`, `mcp_rpc.foil`, `mount.json` and `hyp/runtime.foil` depend
   on the new kernel modules, and a resume rescans mounts from the checkout. So the live test world cannot be booted
   from this working tree at all without first restoring the four files Codex kept in
   `.check/native-views/compatibility-sources/`. The live world has been down since 18:24.
2. **The cycle rule was weakened and the test rewritten to accept it.** `tack_cycle` (`lain_peek.foil:1339-1362`)
   dropped the prefix test: a stored input that contains the cell is no longer a cycle ("Reading stored data does
   not evaluate any cells within it"), and a derived input is a cycle only on exact path equality. Demand cells
   never call `tack_cycle`; a self-reading view burns the 256-fuel and reports "budget exhausted", not a cycle.
   `tests/cells.foil:442-445` was changed from expecting the fault to expecting success. The comment at
   `lain_peek.foil:1229-1230` is now false. The Three Strangers proof 8 relied on the old message. Whether the
   relaxation is right is a design decision Ian should make knowingly; it was made silently.
3. **Views are evaluated on the write path.** `xv_trigger_reader` now runs a demand cell in full to learn its
   triggers (`lain_peek.foil:1169-1171`), and `lain_poke` calls it for every watcher on every commit
   (`lain_poke.foil:536, 886`), outside the cache. `sovereign_reconcile` computes `reference_index/beneath` twice per
   `/r` trigger (`lain_poke.foil:877-878`). Every write to a world with many views pays for the views.

## Other defects, kernel

- **Union variants inserted mid-list** in `helm/card` (`helm.foil:25-27`), `feet/gift` (536-538) and
  `http_foot/action` (`http_foot.foil:10-12`). If tags are positional, any persisted or in-flight message and any
  mount compiled against the old types is misrouted. Append, don't insert.
- **Pinning hole**: a case-pinned `/x` of a demand cell only blocks `live_references` of the record
  (`lain_peek.foil:510, 709`); a dynamic `graft (safe 0 ...)` is not blocked and the reader is not frozen, so a
  pinned read can return current data.
- **`reference_index.past` is unbounded**: one pinned snapshot per epoch that changed a reference, never pruned,
  persisted in the saved namespace.
- **Fuel limits depth, not breadth**: `view_walk/node` loops over every edge (`view_walk.foil:108-122`); when fuel
  runs out the whole answer is `.unknown` and the HTTP layer returns 503 (`graph_http.foil:61-62`). A hub node yields
  nothing instead of a truncated page. Failures are not cached (`view_cache.foil:61`), so they recur in full.
- **Reverse reads scan all descendants**: `beneath` collects edges to everything under the target
  (`reference_index.foil:68-73`); `reverse_view` builds that set per read even for one edge; a short prefix walks the
  whole index unpaged.
- **`cell_address` multiplies cost**: one `resolve_view` per prefix length, called from `xv_case`,
  `xv_trigger_reader`, `data_of` and inside `tack_cycle`'s 64-step loop.
- **`view_ops/referencing` misses pinned inputs**: it builds the `/r` key from the raw path, which is `/h/...` for a
  pinned source (`view_ops.foil:73-74`); `view_walk/node` strips it first and is right.
- **Cache is FIFO, not LRU** (`view_cache.foil:37-38`); render cache lookups are a linear scan with structural
  equality (`view_render.foil:23`).
- **Duplicated code**: the three cached message arms in helm (354-420) and an unreachable uncached copy (423-428);
  `sov/commit` snapshots twice (`shrine.foil:668-684`); `256 0` hardcoded four times; function lookup repeated in
  `cell_over` and `query_start_select`.
- **New reserved top segment `r`** (`is_reverse` is `path.starts('r)`): no world path starts with `r` today, but
  it is a silent reservation.
- **`view_library/seeds`** writes 9 definition records on base install only; a resumed world never gets them unless
  something else installs them.

## Divergences from the Python it replaces (`links.py`), in the graph views

The Python is the behaviour Ian has seen and accepted on the page. Each of these changes what a reader sees.

1. **A thing is not shown once.** Python keeps a page-wide set, expands breadth first so the shallowest place wins,
   and marks repeats `seen` (`links.py:601-616`). Foil tracks only the ancestor trail (`graph_world.foil:110, 122`),
   so a thing reached by two branches expands twice; its `seen` means "ancestor cycle". This is the exact
   over-expansion Ian asked to have fixed on the Doctorow page.
2. **No label merging, no per-folder cap.** Python puts a thing in its first folder with `labels`, `also`,
   `worlds`, `by`, caps a folder at 24 (3 deeper) with `more` (`links.py:645-679`). Foil keys branches by label, so
   one thing appears in every folder that names it; the only bound is the global budget of 32; items past the
   budget in out/part folders render as plain leaves because `deferred` is honoured only for `in` folders
   (`graph_render.foil:111`).
3. **Incoming relations are tagged with the wrong world**: Foil uses the world of the member being described
   (`graph_render.foil:79, 215`); Python uses the world of the record asserting it (`links.py:455`). A 0x12 claim
   about a 0x11 thing is attributed to 0x11. This is the one that breaks "every claim keeps its origin".
4. **Claims are listed as relations.** Python skips holders under `/claims/` and the `claims` label
   (`links.py:543, 586`); Foil drops only `{slot, value}`-shaped records and `graph_tests.foil:94` asserts the
   opposite.
5. **Closed folders count edges, not things** (`graph_render.foil:126` vs `links.py:631, 679`).
6. **Back-edges to ancestors are shown** as cycle items instead of dropped (`links.py:627`).
7. **`moved_to` records are not followed**; the holder climbs past them (`links.py:491-495`).
8. **`same` with a `subject` is found only when a path segment is literally `same`** (`graph_views.foil:115-131`);
   Python falls back to `holder_of` (`links.py:816-823`).
9. **Identity closure capped at 64** (`graph_views.foil:179`); references to targets outside `/user/` dropped
   (`graph_views.foil:376`); disagreements compare exact values, not normalised (`graph_union.foil:70` vs
   `links.py:982`); relation facts merge by name, not identity group; qualifier references stay as paths.
10. **Stubs**: `hole` always false (`graph_views.foil:113`); `around` returns `refs_out`, `refs_in`, `parts` as
    empty arrays (`graph_http.foil:79`); `unfold` accepts only depth 1 or 3 and ignores `open`, `ways`, `labels`
    (`graph_http.foil:131`); only `/graph/by` has an HTTP test.
11. **Per-node cost is unbounded**: every expanded node reruns the identity closure and, per member, every incoming
    edge with a record read and an ancestor walk; the budget bounds nodes, not reads.
12. **Ancestor chain names come from the path's last segment**, not the record's name (`graph_render.foil:243`).

## What to do with it

Keep the architecture (demand protocol, `/r`, addressable children, epoch pins, memory caches). Then, in order:

1. Make the kernel change safe: wire `reindex_references` into resume (or into `mounted-with`) so an old `sov`
   is rebuilt once at boot; append the new union variants instead of inserting; put the cycle decision in front
   of Ian and either restore the prefix rule or document the new one and add a cycle check to demand cells.
2. Take views off the write path: compute a demand cell's triggers from its last observation manifest (the cache
   already holds it), not by re-running it; compute `beneath` once in reconcile.
3. Bound reads, not just nodes: a width cap per folder and per node, truncation with `more` instead of `.unknown`
   on fuel exhaustion, paging on `/r`, prune `past`.
4. Port the Python unfold and union semantics exactly (the 12 divergences above), with the Python output as the
   oracle: dump `/unfold`, `/around`, `/union` from `links.py` for Verisk, McKenzie and Walkaway and diff against
   `/graph/*`. Only then switch `goo-live.js` to `/graph` and capture the "after" latencies.
5. Run the Three Strangers proofs (`extras/mounts/mcp/tests/strangers/proofs.py`) against the native routes with
   `links.py` stopped; proof 8 needs rewording if the cycle rule changes.
6. Delete `snap-before` only after the migration is wired and verified on a fresh clone; delete the other test
   worlds now.

## What Liam said in review, and what it means for this work

1. **"version 0 *cannot* be safely used to mean live: you lose referential transparency. Write a hand to
   synchronize the tack via a crew."** This is the rule the whole branch bends. The hands write live references
   (case 0) everywhere; Codex's views graft and read `safe 0` in 40 places; the `same` judgements across worlds are
   live. Liam's model: a cell's inputs are pinned, and a crew re-pins them in the same event when the input moves
   (the `overlay_cache` pattern). A read at a case then always answers the same. What follows:
   - a view's inputs must be pinned cases, re-pinned by a kook/crew on change, not `safe 0` resolved at read time;
   - the demand protocol can stay, but `graft` must carry the case it read, and `query_origin` must record it;
   - cross-world judgements pin the stranger's case (this was already step 3 of the handoff).
2. **"reee: dispatch thru the namespace."** He wants routing by names in the namespace, not switch statements in
   a mount. Codex's `/graph/{links,by,around,unfold,union}` routes and `mcp_entry` are more switch. The right form
   is what Codex also built: named definitions at `/<self>/weft/graph/*` applied through `/o/<def>/<data>` and
   read through `mcp/read`. The HTTP routes are a second door to the same thing and should go.
3. **"You know what the overhead on pagination is?"** He is wary of mount-side paging over materialised trees.
   Codex's `reverse_view` builds the whole descendant edge set per read and the `/r` prefix read is unpaged; the
   answer is bounded reads in the kernel, not paging in the mount.
4. **"Python tests for e2e are ok for now, but move them into Foil."** Codex did write Foil suites (167 checks);
   keep that direction. The Three Strangers proofs can stay Python until the native routes exist, then move.
5. **"Neuralese is irritating."** Names. Liam's vocabulary is one metaphor: `knit`, `felt`, `dyed`, `sewn`,
   `spun`, `cell`, `weft`, `tack`, `care`, `case`. Codex added `query`, `demand`, `graft`, `projection`,
   `observation`, `manifest`, `locality`, `compose`. Even the indentation differs (`+ name` against his `+  name`).
   Rename before merging: the demand ctor is a `cell` that returns a plan; a `graft` is a `splice`; a `projection`
   is a `read`; `observations` are the cell's `looks`.
6. **"Can you justify this change?" on a hoist in `lain_peek`.** He wants a number or a reason for every kernel
   edit, and he merged #48 only once each was justified. Codex's +554 in `lain_peek` has no such accounting;
   the migration proof and the test counts are not justifications of the read-path changes.
7. **http_foot "a little suspect… probably fine iff only IO-driver visible."** Kernel surface that leaks into
   drivers worries him. Codex's new `http_foot/action` variants mirror `snapshot` and are driver-visible; fold them
   into Liam's `bat` actions rather than adding three.

## Liam's conventions that Codex's code breaks (from the kernel itself)

- **The store knows nothing about lenses.** At HEAD `shrine.foil` never spells `/h`, `/o` or `/x`. Codex's
  `reference_index/signals` builds `/r` paths inside the store and `sov/apply` emits signs at them.
- **Growing histories are sealed.** `ass/span` 8, `track/span` 16, ledger chunks of 256, so the cases ledger
  "pays per touched path, not per known path" (`shrine.foil:238-239`). `reference_index.past` pins the whole index
  per changed epoch, unsealed.
- **Reserved segments live together**: predicates in `lain_types.foil:261-288`, parsers beside `h_parse` and
  `o_parse`, every spelling with an explicit length segment so nothing is found by searching. `is_reverse` sits in
  `lain_peek`; `reverse_address` accepts a spelling without a length; `cell_address` finds a cell by trying prefixes.
- **Records never hold closures** (`weft_std/by_name`: a closure record made every request forty times slower).
  `view_library/seeds`, `graph_mount/install` and `tests.foil:20` write closures into `/sys/weft`.
- **Context never enters data** (the `/x` tree carries no `/sys/view` slot; a66506b, b6e8df7). Codex's grafts
  write `/sys/view/origin` into results, and the walker writes `cycle`, `depth_limit`, `state`, `origins`, `more`.
- **Every `/sys` slot is catalogued** in `slots/system.slots.json`, checked before any suite. About ten new
  `/sys/view/*` slots are not, and `/sys/view/observation/<i>/...` makes a slot a prefix, which `slots/README.md`
  forbids.
- **Bounds are named members** (`ass/span`), failures are named iotas (`'grind_exhausted`). Fuel 256 is a magic
  number four times; cache sizes are inline; exhaustion is a string.
- **One stdlib, by name.** `view_ops` defines `count`, `gather`, `follow` with meanings different from
  `weft_std`'s entries of the same names, under a second root `/weft/namespace`.
- **Names collide.** `query` already means a cased store read (`x_query`) and is a field of `helm/card/interact`;
  `projection` already names `physical_projection`. `graft` is a knitting word and can stay.
- **`/o` is being merged into the cell lens** (`cell_over`, new `/o` arms) against `sys/view.foil:16-17`, and only
  because the `/graph` routes need it.
