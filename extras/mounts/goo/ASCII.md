# Deterministic ASCII measurement (items 14–18)

The native Foil measurer implements `text_style`, `natural_width`, `leaf_size`,
`text_lines`, `leaf_height`, and recursive ASCII validation. It is available as a
library in `ascii.foil` and through the `ascii` inspection action. It does not yet
implement recursive group size summaries, planning, or rendering. Those begin at
item 19; source compilation still exposes the six semantic stages.

## Frozen font data

`fonts.foil` is generated by `scripts/porting/generate-foil-fonts.py` from the
existing `fonts/metrics.json`. Generation verifies source and subset font hashes
and imports all eight faces, 760 glyph advances, units, weights, source names,
italic flags, and hashes. It never rewrites fonts, CSS, Haskell tables, or fixtures.
The build runs the generator in check mode and hashes its inputs. Runtime
measurement uses the compiled tables; it does not query system fonts.

## Numeric and text policy

`binary64.foil` performs finite arithmetic using exact integer fractions followed
by round-to-nearest, ties-to-even binary64 rounding after every operation. This
reuses the validated decimal/bit conversion from item 06. It preserves Haskell's
operation order, including `(line-height ratio * base font size) * scale`, left-to-right glyph sums,
negative tracking, and the strict wrapping comparison with `room + 0.00001`.
Tracking and insets remain unscaled; typography scales, while fixed primitive
sizes retain their existing behavior. Preferred widths use ceiling after the
configured/default cap. The measurer's grow flag is unchanged; the later planner
applies config grow overrides.

CRLF becomes one newline, bare CR becomes newline, and tabs become four spaces.
Text/code retain spaces and break after the last fitting space, hyphen, or slash;
overlong tokens make progress one ASCII character at a time. Empty text and a
terminal newline follow the reference's exact line-count rules. Text status
markers reserve `8 * scale + 5` only on the first paragraph's first line; text
errors gain the existing `! ` prefix. Buttons use collapsed words for natural
width. Role style uses the slot's first segment, while caps and minimum widths
use the exact slot, matching Haskell.

Measured payloads accept printable ASCII plus tab/CR/LF. Recursive failures name
the first unsupported node. Image URLs and config labels are excluded from
geometry/ASCII checks. This does not add Unicode measurement. NUL remains
excluded by the existing Foil JSON transport and is rejected before measurement;
three explicit rejection tests record this distinction from Haskell's ASCII
error. Other representable unsupported controls/text retain the exact diagnostic.

## Inspection protocol

```json
{"version":1,"action":"ascii","tree":{"id":"example","kind":"text","slot":"title","after":null,"text":"Hello world"},"textScale":1,"widths":[80,180,320]}
```

A successful response contains preorder leaf nodes with IDs, style, natural
width, min/pref/grow size, and per-width height/lines. Lines are null for leaves
that do not use text/code wrapping. A malformed semantic tree or invalid scale
or width returns a protocol rejection; unsupported payload returns an ASCII
rejection. Scale must be finite and in `(0,10]`; widths finite and in `[0,100000]`.
The `fonts` action (`{"version":1,"action":"fonts"}`) returns frozen metadata,
glyph units and numeric advances. All calculations and validation run in Foil;
the host only frames the request and preserves decimal lexemes.

## Validation

Build `scripts/porting/build-ascii-oracle.sh`, then run `bin/goo-foil test-metrics`
from this directory (or use the parent-relative commands in README). The oracle
calls the unchanged Haskell `Goo.Ascii.Measure` and `Goo.Ascii.Fonts` functions
directly. It is test-only and is never loaded by the runtime adapter.

The supplemental `python3 goo/scripts/porting/check-ascii-corpus.py` command
(from the parent repository) measures every frozen nonempty semantic tree,
including recursive ASCII failures, at widths 180/320/752.

The suite checks all frozen 7,920 browser-accuracy cases directly against both
stored geometry/lines and Haskell, all faces/advances, extra whitespace/role/
primitive/config/scale cases, unsupported text, and nextafter probes around wrap
thresholds. Valid numbers compare by exact binary64 bits and lines by exact
strings; there is no geometric tolerance. Frozen browser references, font assets,
and prior evidence are verified unchanged. Gate M does not require a browser
layout approximation to justify numeric drift.
